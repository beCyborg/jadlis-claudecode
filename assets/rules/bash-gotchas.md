# Bash gotchas (always loaded — these fire while composing a command, not while reading a file)

Enforced since 2026-10-02 by the PreToolUse hook `~/.claude/hooks/bash-traps.py` (log `~/.claude/logs/bash-traps.log`, bypass `# traps-ok`): `codex exec` → `< /dev/null`, `find /tmp` → `/private/tmp`, `obsidian` in `while read` → `< /dev/null` (rewritten); `gh gist create`, osascript iTerm2 `create window`, recursive grep over `~/.claude/projects` (blocked). Their lines below stay until the hook has run on live sessions.

- `find /tmp …` is a silent no-op: `/tmp` is a symlink and BSD find (default `-P`) does not resolve it even at the start point — write `/private/tmp` (or pass `-H`). Why: three "nothing got deleted" rounds, 2026-08-11; shell globs `ls /tmp/...` are fine (kernel resolves).
- BSD `sort` + `uniq -c` under `en_US.UTF-8` collate different Cyrillic strings as equal and merge counters («Лес» → 6067 instead of 5) — count Cyrillic frequencies inside jq `[…] | group_by(.) | map({v:.[0],n:length}) | sort_by(-.n)`, or `LC_ALL=C sort | LC_ALL=C uniq -c`. Why: silent corruption, inflated numbers look plausible; ASCII keys and `awk '{c[$0]++}'` are safe.
- BSD `env` stops parsing options at the first `name=value` — put every `-u` first: `env -u CLAUDE_CODE_OAUTH_TOKEN CLAUDE_CONFIG_DIR=/x claude`. Why: the reverse order gives `env: -u: No such file or directory`, rc=127 — it killed the 00:10 daily ritual on 02.09.2026.
- System `python3` is 3.9.6 (CommandLineTools) and can fail a long Cyrillic heredoc with `SyntaxError: Non-UTF-8 code starting with '\xd1' in file <stdin>` — write the script to a scratchpad file and run `python3.13 file.py`. Why: it dies before the first write, so a partial run reads as a full one; check with `grep -c` on a marker after a failure.
- pytest will not install into the system Python (PEP 668; do not use `--break-system-packages`) — canonical runner `cd ~/Jadlis && uv run --with pytest --with pyyaml pytest <path>/tests/ -q`. Why: `uv` (`/opt/homebrew/bin/uv`) pulls deps into an isolated env; give test files unique names per skill, identical basenames give `import file mismatch` and a cached `sys.modules` silently tests the wrong module.
- `sips` cannot write webp — `Error: Can't write format: org.webmproject.webp`; use `cwebp -q 82 -resize 640 0 in.png -o out.webp`. Why: inside a batch loop it looks like a harmless `Warning: … not a valid file - skipping` and the files simply are not there.
- `sips -Z` together with `--resampleWidth` lies silently (exit 0, 640 requested → 266×177 from a 1536×1024 source) — use exactly one resize flag and verify with `sips -g pixelWidth`. Why: no error, the image is just small and blurry downstream.
- `uv run --with cairosvg` fails with «no library called "cairo" was found» — prefix `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib`. Why: the uv python does not see `/opt/homebrew/lib`; there is no other SVG→PNG converter on this machine (no rsvg-convert/inkscape/resvg).
- Homebrew 6.0.21+ refuses formulas from a freshly added third-party tap («Refusing to load formula … from untrusted tap») — `brew trust <user>/<tap>` (or `brew trust --formula <full name>`) before install. Why: already-installed taps are unaffected, old untrusted ones only warn.
- `$CLAUDE_SESSION_ID` is empty inside the Bash tool — take the UUID from the scratchpad path (last UUID segment before `/scratchpad`) and pass `WORK_DIR` absolutely. Why: skills building `WORK_DIR` from `${CLAUDE_SESSION_ID}` get `..._slug` without an id and collide across sessions.
- A background `codex exec` / `claude -p` run (verifiers, arbiters, headless agents) gets `timeout: 3600000` (1 h), never 600000 — the background cap is 7200000, the 10-min value is only the foreground cap. Why: on 02.10.2026 the /verif Codex branch (gpt-6-astra, high) on a 35 KB plan was killed at 10 min with no verdict and had to be rerun. Since CC 2.1.288 the background time limit applies only in unattended sessions (`-p`, Agent SDK, CI, cloud); an interactive terminal session has none — keep passing the 1 h `timeout` anyway: it is still enforced inside `-p` runs, and whether subagents of an interactive session count as unattended is unconfirmed (changelog silent, docs still describe the old 30 min / 2 h limit).
- Skills using `Bash(run_in_background: true)` cannot be smoke-tested via `claude -p` — the headless parent exits and kills the child mid-stream. Why: `aborted_streaming` with empty `permission_denials` means "the parent is gone", not a model refusal; test interactively or call the pipeline stages directly.
- `codex exec` under the Bash tool hangs until timeout (exit 143, 0 bytes stdout, `Reading additional input from stdin...`) — append `< /dev/null` to every call. Why: the Bash tool never closes stdin and codex waits for EOF; with the redirect a trivial prompt takes 6 s.
- `claude plugin install <p>@<m> --config KEY=VAL` silently ignores `--config` when the plugin is already installed — it prints «is already installed» and returns 0, leaving `${user_config.KEY}` unset; `uninstall` first, then install with the flag. Why: the only signal is a one-line «N userConfig option not yet set» on the *first* install, and it is absent on the no-op, so a skill later reads the literal `${user_config.KEY}`. Non-sensitive values land in that profile's `settings.json → pluginConfigs`, sensitive ones in its Keychain record — check there, not in the plugin files.

- The Bash tool runs zsh: an unquoted `$var` with spaces is ONE word (`for c in $C`, `git filter-repo $paths`) — use `${=var}` or `eval`, or write the list inline. Why: `git fast-export` usage dump ×8 and `cd: no such file "a b c"` on 07.09.2026, both silent about the cause.
- `brctl evict <path>` no longer exists in Darwin 27 (`brctl -h` lists only diagnose/log/dump/status/accounts/quota/monitor), and `fileproviderctl` has no evict either — iCloud Drive local copies can only be freed from Finder («Удалить загрузку» / "Remove Download") or automatically under disk pressure. Why: `com.apple.bird optimize-storage = 1` looks like eviction is on, but macOS keeps every file local until the disk is nearly full — 14 GB sat locally with zero `.icloud` placeholders on 11.09.2026.
- `security add-generic-password -w "$(jq …)"` with pretty-printed (multi-line) JSON stores the value as HEX — `find-generic-password -w` then returns `7b0a2020…` and Claude Code/jq cannot parse the credentials blob («Invalid numeric literal at line 2»). Always write compact JSON (`jq -c`), and re-read + `jq -e .` right after the write. Why: broke profile B's Keychain blob for one round on 13.09.2026; `~/.claude/scripts/profile-sync-secrets.sh` (A→B sync of mcpOAuth + pluginSecrets) does it right.
- An iCloud Drive file that is not downloaded locally fails with `cp: … Resource deadlock avoided` / `head: Error reading` even with the sandbox off, and Darwin 27 has no `brctl download` — materialize it from Python with `ctypes.CDLL('/usr/lib/libSystem.dylib').setiopolicy_np(3, 0, 2)` (IOPOL_TYPE_VFS_MATERIALIZE_DATALESS_FILES, process scope, ON) and then `shutil.copyfile(src, dst)` (14.09.2026). Why: the Bash tool process runs with dataless-file materialization off, so every read of the placeholder returns EDEADLK; `ls -la` shows the full size and hides that nothing is local.
- `~/bin/obsidian …` (obsidian-cli) reads stdin — inside `while read …; do obsidian eval …; done < list` the first call swallows the rest of the list and the loop ends after one iteration; append `< /dev/null` to every obsidian call in a loop. Why: cost one silent 1-of-10 round on 17.09.2026; same for `dev:screenshot`, which can also hang — wrap it in `perl -e 'alarm 45; exec @ARGV' ~/bin/obsidian dev:screenshot path=…`.
- A shell script must never name a variable `USER`: overwriting it makes `claude -p` answer «Not logged in · Please run /login» (the login keychain is resolved through `$USER`), and the script just returns empty with rc≠0. Name it `USER_MSG`/`PROMPT` instead — the same code inlined in a terminal works, because there `USER` is intact, so the bug looks like «works by hand, fails in the script». Why: cost four bisect rounds on `session-title.sh`, 17.09.2026.
- Anything launchd starts has a minimal PATH: a bare `claude`/`jq`/`tmux` in a script or in `subprocess.run([...])` dies with `FileNotFoundError`, and a fallback path then silently produces garbage instead of an error. Spell binaries absolutely (`~/.local/bin/claude`) or set `PATH` at the top of the script. Why: the TickTick poller named a card by the raw dictated text for an hour, 17.09.2026.
- `plutil -replace ProgramArguments.3 -string X file.plist` on an array index INSERTS at that index instead of replacing — the old element shifts to `.4` and stays (exit 0, `-lint` OK). Follow with `plutil -remove ProgramArguments.4` (or `-remove` first, then `-insert`) and check with `plutil -p`. Why: left a stray `ensure` argument in `com.<you>.jadlis-rituals-ensure.plist` on 20.09.2026; harmless only because the script ignores `$3`.
- Search Claude Code session logs (`~/.claude/projects`, ~9 GB, 16k `.jsonl`, lines up to 1.3 M chars) only with `rg`, and narrow the file set first: `fd --changed-within 7d -e jsonl . ~/.claude/projects | xargs rg …`. Never `command grep`/`xargs grep` over the whole tree, and avoid `.{0,N}` context patterns — use `rg -o` with a bounded pattern or `-M 300 --max-columns-preview` to cap printed line length. Why: a BSD grep with `.{0,120}(…).{0,120}` ran >28 min at 100% CPU over the full tree and made Claude sessions 43% of the Mac's energy use over two hours (23.09.2026).
- Never publish a file as a GitHub gist on the user's account and then point a URL shortener (TinyURL, is.gd) at its raw link — on 29.09.2026 `gh gist create` of a CS2 `autoexec.cfg` + two TinyURL links got `beCyborg` suspended within a minute (API: «Sorry. Your account was suspended», profile 404; suspected anti-abuse trigger, appeal filed the same day). Why: the account also hosts the `jadlis-landing` marketplace; files meant for a phone or another PC go to Obsidian Publish (`publish.obsidian.md/<site>/<permalink>`) instead. is.gd was returning «database insert failed» for every create that day.
- Never script iTerm2 window creation (`osascript -e 'tell application "iTerm2" to create window …'`) from a session that lives in tmux, and never attach two Playwright `--extension` clients (CLI or MCP) to the user's Chrome at once — on 30.09.2026 at 02:08 both happened in parallel test agents: Chrome hung (later killed by a fresh Chrome process, one window lost), iTerm2's main thread stuck inside `iTermNewWindowCommand` at 0% CPU, and the tmux server stopped answering (`tmux ls` hangs, `perl alarm` does not kill it — use `cmd & sleep 3; kill -9 $!`). Why: every `cld` session has `destroy-unattached on`, so the only recovery — killing iTerm2 — ends all of them; which of the two hangs caused the other is unconfirmed. Re-test 07.10.2026: two MCP 0.0.83 extension clients passed one controlled run without a hang; CLI + MCP together was not re-tested — the two-bridge-clients ban stays. The agent's own Chrome profiles (CDP ports 9333/9334, `agent-chrome.sh`) are not the bridge: parallel clients there are fine. Test terminal behaviour in a detached `tmux new-session -d` + `capture-pane`, not in new iTerm2 windows.
- tmux from inside a tmux session: `tmux new-session -d -s X … \; set-option destroy-unattached off` applies the chained `set-option`/`display-message` to the CALLER's session, not to X (the chain's current target is the client you run from) — always pass `-t X` to every chained command. And `tmux display-message -p -t %999 '#{pane_id}'` exits 0 with empty output for a missing pane — test liveness by comparing the output to the id. In zsh, quote `-t '=X'`: a bare `=X` is command-path expansion («X not found»). Why: on 01.10.2026 a test chain switched `destroy-unattached` off on the working session jadlis_B_5, and the old plan-bypass hook's pane check never failed.
- A key changed in `~/.zshenv` (MCP `${VAR}` headers/env, API keys) is NOT picked up by `/mcp` → Reconnect — `${VAR}` expands from the environment the Claude Code process captured at start, so the server keeps spending the old key with no error; restart Claude Code from a fresh shell, and validate a new key with `curl` before editing. Exports in `~/.zshrc` never reach `claude` at all (empty Bearer → HTTP 400). Why: on 01.08.2026 a firecrawl scrape debited the old key (155→154) while the new one stayed at 999.
- macOS has no `timeout` / `gtimeout` (GNU coreutils not installed) — do not wrap commands in it; use the Bash tool's `timeout` parameter or `perl -e 'alarm N; exec @ARGV' cmd`. Why: `command -v timeout gtimeout` is empty on this machine (re-checked 02.10.2026), so a wrapped command dies with «command not found» before it starts.
- zsh applies history modifiers to `$var:…` — `"$vid:read_items"` expands as `$vid:r` (root) + `ead_items`, silently. Brace every variable followed by a colon: `"${vid}:read_items"`. Why: `op service-account create --vault "$vid:read_items"` failed with «…ead_items isn't a vault» on 08.10.2026.
- In the Bash tool (zsh) a bare `log show …` is zsh's builtin `log` («too many arguments», empty output) — call `/usr/bin/log show --predicate …`. Why: three empty unified-log reads on 22.10.2026 looked like «nothing logged» while debugging iPhone Mirroring.
