# Что приезжает в `~/.claude`

## Как сливаются настройки

`scripts/apply-settings.sh` работает через `jq`, а не текстом:

1. Шаблон `assets/settings.template.json` накладывается **поверх** файла получателя —
   по своим ключам побеждает шаблон.
2. Ключи, которых в шаблоне нет, остаются как были: `pluginSecrets`, `enabledPlugins`,
   `pluginConfigs`, любые личные настройки.
3. `env` сливается по ключам — свои переменные получателя не теряются.
4. `permissions.allow` и `permissions.deny` объединяются как множества. `deny` тоже
   объединяется намеренно: заменить его шаблоном значило бы молча снять запрет, который
   человек поставил себе сам.
5. Перед записью старый файл копируется в `settings.json.bak-<дата>-<время>`.

Повторный запуск ничего не меняет и бэкап не пишет.

## Ключи, о которых надо сказать вслух

| Ключ | Значение | Что это значит на практике |
|---|---|---|
| `model` | `opus[1m]` | Opus с окном на 1M токенов. Нужен план **Max**; на Pro эта модель списывает usage-кредиты |
| `permissions.defaultMode` | `bypassPermissions` | агент выполняет команды и правит файлы без вопроса каждый раз |
| `effortLevel` | `high` | больше усилий на ответ; недельная квота расходуется быстрее |
| `outputStyle` | `Jadlis` | стиль ответа для читателя с СДВГ, включён по умолчанию |
| `language` | `Russian` | язык ответов и имён сессий |
| `autoMemoryEnabled` | `true` | память переживает перезапуск сессии, лежит в `~/.claude/memory` |
| `DISABLE_AUTOUPDATER` | `1` | встроенный автообновлятор выключен, обновляет `tools-autoupdate.sh` |
| `statusLine` | `bash ~/.claude/statusline-command.sh` | папка, контекст, модель, лимиты |

Остальные ключи — вкус владельца (тема, формат времени, спиннеры, размеры вывода):
их можно менять после установки, ничего не сломается.

## Файлы

| Файл | Что делает |
|---|---|
| `CLAUDE.md` | глобальные правила: язык, форма планов, маршрутизация, работа с памятью |
| `rules/routing.md` | какой инструмент под какую задачу; читается каждую сессию |
| `rules/bash-gotchas.md` | грабли, которые срабатывают при сборке команды, а не при чтении файла |
| `output-styles/jadlis.md` | стиль ответа: сначала результат, спорить, а не поддакивать |
| `hooks/session-start-title.sh` | подписывает вкладку терминала «`<папка> · HH:MM`», без сети |
| `hooks/rename-topic-from-prompt.sh` | смысловое имя сессии по первому промпту, плану или `/goal` |
| `hooks/_rename-apply.sh` | переименовывает окно tmux |
| `statusline-command.sh` | строка состояния; зовёт `scripts/claude-usage-fetch.sh` |
| `scripts/claude-usage-fetch.sh` | единственный, кому можно спрашивать квоту у API: общий кэш и backoff |
| `scripts/tools-autoupdate.sh` | фоновое обновление `claude`, `grok`, `codex` не чаще раза в 6 часов |

## Хуки: что важно знать получателю

- `rename-topic-from-prompt.sh` по умолчанию работает в режиме `native`: сам ничего не
  генерирует и молчит, имя сессии делает встроенный генератор Claude Code. Ключей API
  не нужно. `TITLE_BACKEND=headless` включает генерацию через `claude -p` на подписке.
- Внутри хука есть мэппинг имён ритуалов владельца (`day-relaunch`, `week-end` и
  прочие). У получателя они просто ни с чем не совпадут — это не ошибка.
- Провал хука = тишина: он никогда не роняет сессию и не пишет `untitled-*`.
- `tools-autoupdate.sh` обновляет `grok` и `codex`, если они установлены; если нет —
  соответствующая строка в логе `~/.cache/tools-autoupdate/update.log` будет с ошибкой,
  на работу это не влияет.
