# Приёмы работы — Claude Code

## Порядок: план → проверка → реализация

1. **План.** Сложную задачу начинай в режиме плана: `Shift+Tab` до `plan mode` или
   команда `/plan`. Агент читает файлы и предлагает план, но ничего не меняет.
2. **Проверка.** План, у которого дорогая цена ошибки, отдай на состязательную проверку —
   `/verif` (плагин `jadlis-verif`, ставится отдельно). Дешёвый план проверять не надо.
3. **Реализация.** Принял план — агент выполняет его. Возражения по ходу лучше писать
   сразу, а не в конце.

Мелкая правка проходит без всего этого: сказал → сделал → посмотрел дифф.

## Сессии `cld`

- `cld` в папке проекта открывает новую tmux-сессию и запускает в ней Claude Code.
- Имя сессии = имя репозитория из `git remote`, иначе имя папки. Вторая сессия в той же
  папке получит суффикс: `jadlis`, `jadlis_2`, `jadlis_3`.
- Вкладка iTerm2 подписывается темой разговора: сначала «`<папка> · HH:MM`», потом
  смысловым именем по первому сообщению.

## Вернуться к прошлой сессии

| Что нужно | Как |
|---|---|
| Сессия ещё жива в tmux | `tmux ls`, затем `tmux attach -t <имя>` |
| Продолжить последний разговор в этой папке | `claude --continue` |
| Выбрать разговор из списка | `claude --resume` |
| Посмотреть, что было | `/resume` внутри сессии |

## Мелочи, которые экономят время

- Файл в промпт — через `@путь`; имя заметки — через `[[вики-ссылку]]`.
- `/goal <условие>` держит цель сессии и переименовывает её по смыслу цели.
- Ответы слишком длинные или слишком короткие — дело стиля `Jadlis`
  (`~/.claude/output-styles/jadlis.md`), его можно править под себя.
